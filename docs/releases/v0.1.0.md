# VolArb v0.1.0 — Execution Infrastructure Foundation

VolArb's first repository release establishes reusable execution architecture, provider-neutral broker contracts, the Dhan connector, deterministic testing infrastructure and a coherent research/source layout. These foundations are implemented and validated offline. **The complete generic Execution Engine runtime is still under development; this is not an autonomous production trading platform.**

## Highlights

- Strategy-independent Execution Engine identity, preserved VIDs and explicit provider/strategy boundaries.
- Implemented Dhan Broker Execution Port and global error normalization.
- Deterministic primitives and component/composition/scenario/mass-test harnesses.
- Separate test, replay, shadow and production dependency declarations.
- Repository-wide consistency repairs, structured archives, canonical navigation and a refreshed README with original VolArb identity.

## Execution architecture

`component.execution_engine` is canonical in the immutable `[5,0,...]` namespace. All 100 canonical execution identities are preserved. Compositional identity separates reusable component definitions, strategy mounts/bindings and runtime instances. An optional Strategy Execution Adapter owns strategy-specific translation; the engine does not own butterfly semantics or financial governance.

Implemented source covers broker vocabulary, structural runtime ports and shared errors. Margin Optimization → Execution Slicing → Optimal Execution → Execution Recovery / Command Commit Guard is the **designed** policy path, with cross-cutting State Integrity, Recovery and Interrupt Control—not a completed executable pipeline.

## Broker layer and Dhan Provider

The Broker Execution Port provides provider-neutral QUERY / COMMAND / STREAM vocabulary. Dhan implements configuration/readiness checks, neutral instrument/order translation, placement/modification/cancellation primitives, positions/orders/trades/funds/margin queries and recovery lookup by order/correlation identifiers. Market and order-update stream adapters, correlation projection and global Provider Error Envelope normalization are present.

Dhan owns mechanical broker translation and transport, not strategy or execution policy. Mutation primitives are gated; ambiguous outcomes require reconciliation rather than blind retries. Synthetic tests use injected transports and do not establish real-account authentication, exchange fidelity or live readiness. Provider package `0.3.0` and architecture manifest `1.4.0` retain their independent versions; stale HTTP User-Agent labels are aligned to the package version.

## Execution Testbed

Implemented infrastructure includes `VirtualClock`, `SeededRng`, causal traces, `SimulatedMarket`, `SimulatedBroker`, `FaultInjector`, `MemoryExecutionLedger`, component/composition harnesses and caller-driven scenario/mass runners. Trace invariants check overfill, ledger-before-mutation, stale intents and blind duplicate placement after ambiguity. Failed mass cases retain reproduction seeds and fixtures.

Tests exercise fixture components, a 25-order campaign and 1,000 lightweight seed-addressable smoke cases. The full-engine scenario harness exists, but complete-engine coverage awaits real engine components. The in-memory ledger and scripted broker are test doubles, not production persistence or a calibrated exchange simulator.

## Environment separation

| Environment | Intended dependencies |
|---|---|
| Test | Simulated broker/market, virtual clock and memory ledger |
| Replay | Recorded observations, simulated broker and virtual clock |
| Shadow | Live read-only observations; no broker mutations |
| Production | Real providers, real clock and durable ledger; `execution-testkit` forbidden |

These are dependency **declarations**, not an implemented environment loader. The design requires the same engine code with injected dependencies in every environment, never a second test engine or production test-only branches. Dedicated replay ingestion and live-shadow runners remain future work.

## Compatibility

- `component.internal_execution` is a **legacy compatibility alias**; canonical execution VIDs are not renumbered.
- Legacy butterfly-executor/MCP surfaces are retained and separately gated; they are not the new generic engine.
- Repository `0.1.0` does not replace Dhan `0.3.0`, kit/laboratory `0.1.0`, architecture or skill versions.
- This is a normal initial-development `0.x` source milestone, not a 1.0 stability promise or production-readiness label.

## Known limitations and next work

Implement the real policy/recovery components, durable ledger boundary and environment loader, then exercise them through the existing component/composition harnesses and complete-engine scenarios. Replay/live-shadow runners and broader calibrated simulations follow; additional brokers remain future work. Dhan stream reconnection/backoff and health hardening, provider-local rate-limit telemetry and broader instrument normalization remain work; separate 20/200-level depth feeds are not implemented. No live production validation was performed for this release.

This release does not deploy services, enable mutations, change credentials, create schedules, monitor markets or place orders. GitHub's automatic source archives are the only release downloads; private logs, state and broker data are not attached.
